# Public-release checklist

## Repository

- [ ] Create or make public `rsolerortuno/activation-liability`.
- [ ] Upload the contents of the public release ZIP, not the outer folder.
- [ ] Enable GitHub Actions.
- [ ] Confirm README images render.
- [ ] Create tag `v0.5.0`.
- [ ] Attach ZIP and SHA-256 to the GitHub release.
- [ ] Optionally enable GitHub Pages from `/docs`.

## Drive

- [ ] Share https://drive.google.com/drive/folders/1f3K-MzEQDsUFmMIb5cnFxH47_G-HYPKN as **Anyone with link → Viewer**.
- [ ] Keep editing restricted to named accounts.
- [ ] Verify release and result folders open without login.
- [ ] Keep GSE190564 in https://drive.google.com/drive/folders/11hz8VhGV2bcSGp3dWmeQlufIsIeZQAzF.

## Scientific truthfulness

- [ ] State that v0.5.0 is RNA-led and not clinically validated.
- [ ] State that GSE190564 is planned, not analysed.
- [ ] Do not claim toxicity prediction or therapeutic-window estimation.
- [ ] Retain the CD79A and CD69 context-dependent benchmark failures.
- [ ] Include source checksums and claims contracts.

## Optional archival release

After the GitHub release is final, connect the repository to Zenodo to mint a DOI. Do not create a
DOI until the public files and citation metadata have been checked.
